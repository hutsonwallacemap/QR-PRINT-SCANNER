01 · Overview

Connection map

Everything runs on the shop PC except two outside services: the registry on Vercel, which gives every shop a QR link that never changes, and Razorpay, which confirms online payments. Customers arrive by one of two roads: shop Wi-Fi straight to the PC, or mobile data through the registry and a Cloudflare tunnel.

02 · Network

How a phone reaches the shop

The free Cloudflare address changes every time the PC restarts, so the poster never shows it. The poster shows the registry link, and the shop PC keeps the registry told where it is now.

03 · Money

Three ways to pay, and who releases the print

A plain UPI link sends nothing back to the shop, so software cannot know if money arrived. Only Razorpay can release a print by itself. The other two wait for one tap from the shopkeeper.

Razorpay

Print starts by itself
  1. Shop PC creates a Razorpay order for the exact amount.
  2. Customer pays by UPI or card inside the page.
  3. Razorpay returns a signature; the PC checks it with the shop's secret key.
  4. Match → order goes to the print queue.
  5. Page closed early? The PC asks Razorpay every 20 s.

UPI ID

Shopkeeper taps Paid ✓
  1. Customer opens their UPI app with amount and token filled in.
  2. Customer taps "I have paid" and can add the UTR.
  3. Dashboard beeps: "Customer says paid · UTR …".
  4. Shopkeeper checks the bank app, taps Paid ✓ → prints.

Cash at counter

Shop chooses the rule
  1. Confirm first: prints after Paid ✓.
  2. Print first: prints now, shopkeeper taps "Cash received" later.
  3. Or turned off entirely.

08 · Trust

Security layers

ThreatWhat stops it
Printing without payingRazorpay signature + API check, or shopkeeper's Paid ✓. The "I have paid" button never prints.
Changing prices or the UPI IDDashboard needs the PIN (stored hashed, PBKDF2). First PIN can only be set on the shop PC itself, never through the tunnel.
A website tricking the shopkeeper's browserAdmin actions need a custom header and a same-site cookie.
Seeing someone else's orderEvery order has a private random key in the customer's link.
Hijacking a shop's QRRegistry locks each shop ID to that shop's secret; https targets only.
Malicious file namesAll names shown as text, never as HTML; unsupported or damaged files refused.
Wrong price from the phonePrice always recalculated on the PC from the shop's own rates.
Double print after a crashInterrupted jobs marked failed; the shopkeeper decides to Retry.

10 · One order, start to finish

A customer on 4G, in plain steps

  1. Scans the poster. Phone opens the permanent link; registry forwards to the shop's current tunnel.
  2. Uploads two files. The PC checks each opens, counts pages, shows a preview.
  3. Chooses colour, 2 copies, pages 1-3. Price shows live; the PC recalculates it on Review.
  4. Taps Pay ₹80 online. Gets token #105. Razorpay checkout opens; pays by UPI.
  5. PC verifies the signature, queues the order. Dashboard updates; no tap needed.
  6. Print worker renders each page, applies colour and paper settings, sends "Token 105" to the printer.
  7. Phone shows Ready. Customer says "105" at the counter and collects.
  8. An hour later the files are deleted from the PC. The order stays in the daily report.
